01 / 画面構成

模式図です。JRAのページでは東京・京都などの開催場が並びます。HTMLをまとめても、取得データと結果は会場別に保存します。

共有したURLで同じ会場・レースを開ける形にし、タブを切り替えても読んでいた場所を残します。

02 / 結果表示

印と着順は、いつでも見える。

  • 馬番・馬名・事前の印・何着だったかを同じ一覧に表示。
  • 「結果を更新」で公開済みの結果を再読込。公式の確認時刻を表示。
  • 速報の上位着順も残し、未掲載の馬は保留。
  • 取得失敗でも前の結果を残す。全対象の確定後は自動取得を停止。
  • 公式を最終判定に使用。非公式の速報には出典と未照合を表示。

地方の10/7ページには結果取得・着順表示を実装済み。JRAには公式結果の取得処理がありますが、公開ページのボタンと継続取得は未接続です。非公式の取得処理も未実装です。

03 / 買い方

本線と、三連単の別案を分ける。

  • 全買い目・点数・1点の金額・合計・価格条件を表示。
  • 1着固定にする馬と、2・3着で残す馬の理由を示す。
  • 別案を全部足して予算にしない。レース上限と1日上限を確認。
  • 「予定」「見送り」「購入済みの申告」を端末に記録。
  • 実購入が不明な収支は仮想検証。結果を見て作った案は説明用。

共通の買い方・予算補助を開く →

単勝・複勝・ワイド・馬連・馬単・三連複・三連単を扱います。購入記録は端末内に保存。実投票・オッズ取得・記録の自動精算は行いません。

04 / 保存と引継ぎ

同じ仕様書を両チャットから参照。

完成した予想は同じKBAリポジトリへコミット・プッシュします。事前の予想原本は保持し、結果と反省は別に保存します。

共通仕様の全文
画面・更新・購入補助・GitHub公開・実装状況共通のデータ項目
券種・着順・価格・購入記録・JRAと地方の変換対応

両作業フォルダに参照指示を保存。別チャットの会話履歴を自動共有する仕組みではありません。

05 / 次回の作成で揃える順序

共通化の残りの作業

  1. 開催日の共通テンプレートと競馬場タブ。
  2. JRA・地方のデータ変換と共通の結果表示。
  3. JRAの継続取得、次回開催日の登録と公開処理。
  4. 予想から購入補助への引継ぎ、購入JSONの取込と精算。

今回保存したのは共通仕様・参照指示・公開スクリプトの互換対応・購入補助の拡張です。既存の全予想ページのタブ移行とJRAの自動取得接続はこれからです。今回のコード変更の実行による動作確認は行っていません。
